Builder Design Pattern – Complete Theory Notes (LLD / System Design)
1. Introduction to Builder Design Pattern
The Builder Design Pattern is a Creational Design Pattern in Low-Level Design (LLD).

It is used to create complex objects step by step. It separates the construction process of an object from its final representation.

In simple language:

Builder Pattern allows us to create an object by setting its properties one by one instead of passing all the properties through a single constructor.

For example, imagine we want to create a Computer. A computer can have multiple properties:

RAM

Storage

Processor

Graphics Card

Motherboard

Operating System

Some properties are mandatory, while others are optional.

Instead of passing all these properties into a constructor, Builder Pattern allows us to configure the computer step by step.

2. Why do we need Builder Design Pattern?
Before understanding Builder Pattern, we need to understand the problems that occur when creating complex objects.

Problem 1: Constructor with too many parameters
Suppose we have a Computer class:

Computer c(16, 512, "Intel i7", true, false, true);

Here, we are passing multiple values into the constructor.

Problems:

Difficult to understand what each parameter represents.

Difficult to remember the order of parameters.

More parameters make the constructor complicated.

Code becomes difficult to maintain.

Problem 2: Too many optional parameters
Consider a Computer object.

Some computers have a graphics card, while others do not.

Some computers have additional storage, while others do not.

If we use constructors, we may need multiple constructor combinations.

For example:

Computer(int ram);

Computer(int ram, int storage);

Computer(int ram, int storage, string processor);

Computer(int ram, int storage, string processor, bool gpu);

This creates unnecessary complexity.

Problem 3: Constructor overloading
When an object has many optional properties, we may need to create multiple constructors to support different combinations.

This makes the code difficult to manage.

Solution: Builder Pattern
Builder Pattern solves these problems by allowing us to construct objects step by step.

Instead of passing everything into one constructor, we can write:

ComputerBuilder builder;

Computer computer = builder
                    .setRAM(16)
                    .setStorage(512)
                    .setProcessor("Intel i7")
                    .setGraphicsCard(true)
                    .build();

This makes object creation more readable, flexible, and maintainable.

4. Definition and main idea
The Builder Design Pattern separates the construction of a complex object from its representation.

Its main idea is to:

Create an object step by step.

Configure its properties individually.

Support optional parameters.

Avoid complicated constructors.

Make object creation readable.

Return the final object after construction is complete.

The same construction process can also be used to create different configurations of an object.

5. Components of Builder Design Pattern
Builder Pattern generally consists of four main components.

LLD: Builder Design Pattern (Creational) | by Concept && Coding - by Shrayansh | Medium

1. Product
Product is the actual object that we want to create.

It contains the properties and methods of the final object.

Example:

Computer

House

Car

Pizza

HTTP Request

In our example, Computer is the Product.

2. Builder
Builder defines the methods required to construct the product.

It provides methods for setting different properties of the object.

For example:

setRAM()

setStorage()

setProcessor()

setGraphicsCard()

It also provides a method to return the final object, usually called build().

3. Concrete Builder
Concrete Builder implements the construction process defined by the Builder.

It is responsible for:

Setting object properties.

Managing the construction process.

Returning the final product.

In a simple C++ implementation, the ComputerBuilder class acts as both the Builder and Concrete Builder.

In more advanced implementations, an abstract Builder interface and separate Concrete Builder classes can be used.

4. Director
Director controls the sequence of steps used to construct an object.

It tells the Builder which steps should be executed and in what order.

For example, a Director can provide predefined configurations:

Gaming Computer.

Office Computer.

Professional Workstation.

The Director does not construct the product directly. It uses the Builder to construct it.

Important: Director is optional. The client can directly interact with the Builder.

5. Client
Client is the part of the program that requests the object.

It creates or uses the Builder and optionally the Director to obtain the final product.

In our C++ example, main() is the Client.

6. Working of Builder Design Pattern
Builder Pattern follows a step-by-step construction process.

The general workflow is:

Step 1: Client

Requests a complex object

Step 2: Builder

Initializes the object with default values

Step 3: Configuration

Sets required and optional properties one by one

Step 4: Build

Finalizes and returns the object

Step 5: Product

Final configured object is ready to use

Let's understand each step.

Step 1: Client creates a Builder object.

Step 2: Builder initializes the object with default values.

Step 3: Client calls different setter methods to configure the object.

Step 4: Builder's build() method returns the completed object.

Step 5: Client receives and uses the final product.

7. Important concepts used in Builder Pattern
There are some important C++ concepts commonly used in Builder Pattern.

A. Method Chaining
Method Chaining means calling multiple methods continuously on the same object.

Example:

builder.setRAM(16)
       .setStorage(512)
       .setProcessor("Intel i7")
       .build();

Instead of calling every method separately, we can call them continuously.

This is possible because each setter returns the same Builder object.

B. this pointer
In C++, this is a special pointer available inside non-static member functions.

It points to the current object that calls the function.

For example, if a Builder object calls setRAM(), then this points to that Builder object.

C. *this
The * operator dereferences a pointer.

Therefore:

this represents the address of the current object.

*this represents the actual current object.

Example:

ComputerBuilder& setRAM(int ram) {

    computer.ram = ram;

    return *this;
}

Here, return *this returns the current Builder object by reference.

This enables Method Chaining.

D. Reference return type (&)
When we write:

ComputerBuilder& setRAM(int ram)

It means the function returns a reference to an existing ComputerBuilder object.

It does not create a separate Builder object.

Returning a reference also avoids making a copy of the Builder object at every setter call.

E. build() method
The build() method is responsible for returning the final product.

For example:

Computer build() {
    return computer;
}

Unlike setter methods, which return the Builder, build() returns the completed Computer object.

8. Role of Director in Builder Pattern
Director is an optional component that controls the construction process.

Suppose we want to create multiple types of computers.

Without Director, the client has to configure every computer manually.

With Director, we can define reusable construction procedures.

For example:

Processor

1 TB

Intel i9

Office PC

8 GB

256 GB

Intel i5

Director provides predefined construction procedures for these configurations.

Important distinction:

Builder knows how to set the individual properties.

Director knows which construction steps to execute.

Client decides which configuration to request.

9. Advantages of Builder Design Pattern
1. Improves readability
Object creation becomes easier to understand because properties are configured individually.

2. Handles optional parameters
We can configure only the properties required by the client.

3. Avoids complex constructors
We do not need constructors with too many parameters.

4. Supports method chaining
Multiple methods can be called continuously on the same Builder object.

5. Improves maintainability
Adding new optional properties becomes easier without changing a large constructor.

6. Separates construction from representation
The process of constructing an object is separated from the final Product class.

7. Supports different configurations
We can create different versions of the same product using the same construction process.

8. Allows validation
We can validate mandatory properties before returning the final object from build().

For example, a computer must have a valid RAM size and processor before it can be built.

10. Disadvantages of Builder Design Pattern
1. Increases code complexity
It requires additional classes and methods.

2. Not suitable for simple objects
If an object has only two or three properties, using Builder Pattern may be unnecessary.

3. Requires additional maintenance
Changes in product properties may require changes in Builder implementations.

4. Mutable Builder concerns
If the same Builder object is reused, previous property values may remain. The developer must handle resetting or initialization carefully.

5. More code to write
For small applications, normal constructors may be simpler and more efficient to implement.

11. When should we use Builder Pattern?
Builder Pattern is useful in the following situations:

When an object has many properties.

When an object has many optional parameters.

When constructors become difficult to understand.

When multiple configurations of the same object are required.

When object construction involves multiple steps.

When we need validation before creating the final object.

When we want readable and maintainable object creation code.

When should we avoid it?

When objects are simple and can be created easily using a normal constructor.

15. Important interview questions and answers
Q1. What is Builder Design Pattern?

Builder is a Creational Design Pattern used to construct complex objects step by step while separating the construction process from the final representation.

Q2. Why do we use Builder Pattern?

We use it to handle complex object construction, optional parameters, and constructors with too many arguments.

Q3. What is Method Chaining?

Method Chaining is the technique of calling multiple methods continuously on the same object.

Q4. Why do we use return *this?

It returns the current object by reference, allowing us to call another method on the same object.

Q5. What is the role of Director?

Director controls the sequence of construction steps and can provide predefined object configurations.

Q6. Is Director compulsory?

No. The client can directly use the Builder to create an object.

Q7. Can Builder Pattern handle optional parameters?

Yes. It allows the client to configure only the required optional properties.

Q8. What is the difference between Builder and Factory?

Factory focuses on creating the appropriate object, while Builder focuses on constructing a complex object step by step.

Q9. Can we validate an object in Builder Pattern?

Yes. We can perform validation inside the build() method before returning the final object.

Q10. What is the main disadvantage of Builder Pattern?

It introduces additional classes and code, so it may be unnecessary for simple objects.
