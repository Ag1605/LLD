1. What is Iterator Design Pattern?
Iterator is a behavioral design pattern.

It provides a way to access elements of a collection one by one without exposing the internal structure of that collection.

In simple words:

Iterator Pattern allows us to traverse elements of a collection sequentially without knowing how the collection is internally implemented.

For example, imagine you have a list of students.
ou want to access:
- Student 1
- Student 2
- Student 3
- Student 4
You don't need to know whether students are stored in an array, linked list, or another data structure.

You just need a way to move from one student to the next.

That's what Iterator Pattern does.
2. Why do we need Iterator Pattern?
Suppose we have an array:
int arr[] = {10, 20, 30, 40};


We can traverse it using a loop:
for (int i = 0; i < 4; i++) {
    cout << arr[i] << endl;
}


Now suppose the collection changes to a linked list.

The traversal logic will also change.

This creates unnecessary dependency between the client and the internal data structure.

Iterator Pattern solves this by providing a common way to traverse collections.

The client only needs to call:
iterator->next();


It doesn't need to know how the collection stores its elements.
3. Real-life example
Think about a music playlist.
Suppose your playlist contains:
Playlist
   |
   |--- Song 1
   |--- Song 2
   |--- Song 3
   |--- Song 4


You can perform operations such as:
- Play current song.
- Move to next song.
- Check whether another song exists.
- Access previous song.
The iterator manages the current position and helps you navigate through the playlist.
4. Main components of Iterator Pattern
There are four important components.
1. Iterator
Defines the interface for traversing elements.

It generally provides methods such as:
- hasNext()
- next()
Example:
class Iterator {
public:
    virtual bool hasNext() = 0;
    virtual string next() = 0;
};


2. Concrete Iterator
Implements the actual traversal logic.

It maintains the current position in the collection.

Example:
class PlaylistIterator : public Iterator {
private:
    int index;
};


3. Aggregate
Defines the interface for creating an iterator.

Example:
class Playlist {
public:
    virtual Iterator* createIterator() = 0;
};


4. Concrete Aggregate
Contains the actual collection of elements and creates its iterator.

Example:
class MusicPlaylist : public Playlist {
};

        6. How does Iterator Pattern work?
Let's take a music playlist example.

Suppose we have:
Playlist:
Song A
Song B
Song C


Execution:

Step 1: Create a playlist.

Step 2: Create an iterator for that playlist.

Step 3: Iterator starts at index 0.

Step 4: Call hasNext() to check whether an element exists.

Step 5: Call next() to get the current song and move forward.

Step 6: Repeat until no elements remain.

Example:
while (iterator->hasNext()) {
    cout << iterator->next() << endl;
}


Output:
Song A
Song B
Song C


7. Advantages
1. Encapsulation: Hides the internal structure of a collection.
2. Simplifies traversal: Provides a common way to access elements.
3. Loose coupling: Client doesn't depend on the collection's implementation.
4. Multiple traversals: Different iterators can traverse the same collection independently.
5. Flexibility: We can change the underlying collection without changing client traversal logic.
8. Disadvantages
1. Introduces additional classes and interfaces.
2. Can be unnecessary for simple collections.
3. Some iterator implementations need careful handling when the collection changes during traversal.
4. Custom iterators can add complexity compared with built-in loops.

10. Iterator vs Composite vs Flyweight
Pattern	Main purpose
Iterator	Traverse elements one by one
Composite	Treat individual objects and groups uniformly
Flyweight	Share objects to save memory
Proxy	Control access to objects
Bridge	Separate abstraction and implementation
